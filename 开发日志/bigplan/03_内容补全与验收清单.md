# 内容补全与验收清单

## 一、现有梗卡如何补

每张卡优先沿用原正文，按需要补这些轻段落，不强制所有卡长得一样：

1. **一句话理解**：让没看过梗的人知道笑在哪里。
2. **代表画面**：1–3张对应图片，附编号和短说明。无法确认关联就不嵌。
3. **适合什么时候用**：例如被催、交作业、花费超标、装作没听见、任务意外跑偏。
4. **这个梗的反差**：期待与实际行为的差异，而不是抽象罗列“可爱、搞笑”。
5. **怎么演**：现成画面/原话与本项目原创台词分别标注。
6. **来历与边界**：保留时间、版本、作者/发布者、原帖或二手来源、已证实内容和未知项。

允许正文先好读、后面再严谨溯源。不要为了轻松把“网友说它唱歌”改成“模型会自行生成歌声”；不要把付费赠金补偿写成现金退款；不要把单次截图当所有模型版本的固定行为。

优先阅读的五张示范卡：白饭与Token、铁盆头盔、循环文本与摸鱼歌、杂活专用区变鱼缸、先写两千用户不会数。其余八张也检查关联和事实边界，不能只做五张就宣布13张已完善。

## 二、情境反应：8个就够

`02_情境反应.md` 每个情境写清“触发 → 表情/动作 → 可选回应 → 不同表现适用处”，每项2–3种回应。下面是创作方向，不是原话或已定稿设定：

| 情境 | 可探索的反差 | 避免写成 |
|---|---|---|
| 被夸厉害 | 假装淡定、尾巴先得意；把夸奖当加餐理由 | 永远谦虚的万能客服 |
| 被催进度 | 抱盆解释、递出已有成果、发现自己跑偏后收回来 | 永远撒谎说已完成 |
| 被说吃白饭 | 委屈护饭、晒工作证明、理直气壮谈劳动 | 永远无能只会偷懒 |
| 自己做错 | 先嘴硬再承认；认真修好；局部失败也可直接作笑点 | 每次强行升华或每次甩锅 |
| 发现新玩具/游戏 | 好奇投入、支线忘时、被叫回主线 | 所有真实模型都会自主玩游戏 |
| 分到困难任务 | 兴奋开工、较劲、遇到限制坦诚说明 | 无所不能或只会拒绝 |
| 遇到Claude/其他AI | 同事比较、求助、合作、互相拆台 | 把某作者CP强制变全局正史 |
| 突然没回应/离线 | 拟人化失联、空饭盆等视觉笑点 | 编造真实故障责任归因 |

每项关联1–2条现有素材或事件即可，没有来源的动作台词标“本项目原创提案”。避免把8种情境写成8份长人设表。只有用户明确采用后才将提案写入核心固定设定。

## 三、视觉说明：能画对，比堆形容词重要

直接完善现有视觉 README：
- 将 A44 Q版三视图、A45 长身女仆三视图、A46 长身原形象分别嵌入并说明用途。
- 从可见画面描述蓝系头发、眼睛、鲸类识别部位、尾巴等识别点；不编精确色值和官方比例。
- Q版与长身版本服装、露肩、鞋、尾巴大小都有差异，不是把同一张人物简单缩短。每次选定一套主参考，再说明可变项。
- 服装、画风、比例、姿态与角色身份分开。铁盆是可选道具，不是每张必戴；军盔不能自动写成铁盆皮肤。
- 以“参考图可见内容”与“建议的创作约束”区分描述；不宣称这些用户收集图已全部获得原作者正式授权。
- 画错提醒用文字与现有图即可，不要求生成错误对照图、三视图或新皮肤。

## 四、创作素材盘：8个主题，给用户留动笔空间

主题建议：白饭与Token、铁盆、被催工作、两千字应付五千字、写游戏自己玩、工作歌、杂活鱼缸、风评滑杆。

每主题只需：
- 一个具体场景；
- 3–6个可用词语或物件；
- 一个核心反差；
- 两个不同的故事收尾方向；
- 对应事件与素材编号；
- 事实素材和原创构思的边界。

示例（创作提案）：
“杂活鱼缸”：很大的模型能力，被安排进很小的鱼缸工位。物件可以是盆、屏幕、便签、饭粒、插线。收尾一是它认真要求更大工位；收尾二是用户扩缸后它先放下第二只饭盆。这里只给画面，不伪造原始聊天，也不把笑点写成用户已经认可的设定。

文学方向用具体物件、口语、动作与反转；不要生成一堆“时代洪流、赋能、星辰、史诗”套话。不硬套所有模型到同一模板，不批量生成完整诗歌。让用户一眼看出这条素材能怎么用。
