## 2. 一张图只选一个物理位置

分类优先顺序：实际多帧 GIF → 动态表情；以软件/聊天记录为主体 → 对话与过程截图；主要为连续故事或多格组合 → 漫画与拼图；真人照片等辅助参照 → 人物与其他参考；其余反应表情、票券、鱼缸设计等 → 静态表情。

混合截图与漫画，按主要阅读用途选一处，另一用途写标签即可。不要为了争论分类拆图、裁图，或同时复制到多个目录。同一素材可被多本图册、多个事件引用。

注意实例：A17 是军用头盔场景，不是铁盆；A32 是烹饪锅具，不是头盔；A43 的人物身份不能仅凭人脸辨认来确定，只能保留文件提供的信息与来源限制。

## 3. 命名与编号

建议模式：`大肥鱼_A06_先写两千字用户不会数.png`。

- 保留已有 A01–A46；A01 不属于大肥鱼。新图取未使用的下一个编号，既有编号永不复用。
- 展示名可以优化，编号不随标题、分类或顺序变化。
- 简短中文描述即可，不把整段台词或来源 URL 塞进文件名。
- 避开 Windows 非法字符、结尾空格/句点与过长路径；不要仅靠大小写区分文件。
- 识别真实格式后允许纠正错误后缀，但只能改名，不转码。当前有 6 个 `.jpg` 实为 PNG，具体以清点结果为准。
- 不改动像素、不重新压缩、不去水印、不补字、不修改 GIF 帧或时长。
- 视觉3图、GPT1图可保持原名；仍纳入统一映射的保留项。

## 4. 三份现有记录各做什么

### 原始素材清单.json：历史快照

根文件使用 `images` 数组，记 46 个原图片文件；其中 `file_count=48` 是当时原仓库文件总数，不等于图片数，也不等于当前仓库文件数。`unique_image_blobs=45` 是原始去重字节种类数，不是允许保留的文件数。

保留这份清单的原路径和历史基线不变。迁移后由 README 说明它是历史清单，当前路径见迁移映射。不要让检查器把历史路径全部判作当前破链。

### 素材索引.json：当前可用目录

位于 `DeepSeek大肥鱼/模型事迹及其表情包/素材索引.json`，顶层 `items` 是 42 个鱼表情条目。

保留现有 id、name、type、scene、emotion、props、text、meaning、credits、notes、privacy、events、review、source_url、git_blob_sha、bytes、width、height、format、frame_count、permission_status 等字段。只需更新当前 `path`，按实际需要补充少量字段，不要先重设计一整套数据模型。

- `path`：仓库根相对路径，统一 `/`。
- `events`：事迹目录里的文件名数组，解析基目录固定为 `DeepSeek大肥鱼/模型事迹及其表情包/事迹/`。空数组合法；目前有17项为空，不强行编造出处。
- 可选新增 `tags`：每图约2–5个实用词，例如白饭、嘴硬、被催、委屈、得意、工作、失联、关系。不是强制凑满。
- 可选新增 `uses`：诗歌取材／表情回复／短漫动作参考等，不需要复杂权重。
- GIF 的 `duration_ms`、`motion_review` 仅适用于动图，不要求静态图填写虚假数值。
- `source_url` 中固定旧提交的 GitHub 链接是“收到这份文件的位置”，不是首发原帖；不要覆盖成当前路径后丢失出处。若已知真实原帖，可另加 `origin_url`、`origin_author`，未知用空值或明确未知，不猜。
- 许可、可见署名、隐私提醒与已核实限制必须保留，不能用默认 CC 许可批量覆盖。

### 素材迁移映射.json：旧路径到新路径的桥

建立一份覆盖全部46图的映射；执行时新增加的图另外记录并说明。每项至少：

```json
{
  "id": "A06",
  "old_path": "DeepSeek大肥鱼/表情包/1792333424105.png",
  "new_path": "DeepSeek大肥鱼/表情包/对话与过程截图/大肥鱼_A06_先写两千字用户不会数.png",
  "git_blob_sha": "从真实清单读取，不手填示例哈希",
  "action": "move"
}
```

这是字段示意，实际分类必须看过图片后决定。未移动项 old_path 与 new_path 相同，action 为 keep。记录执行前提交与日期。不要把本机下载目录、临时文件绝对路径写进仓库。

## 5. 迁移步骤与校验

1. 建立完整映射，检查目标路径不冲突，保证每个旧路径唯一对应一个新路径。
2. 文件移动后计算 Git blob SHA：用 `git hash-object 文件`，或按照 Git blob 格式计算；不要把普通文件 SHA-1 当作 Git blob SHA。
3. 比较迁移前后的“路径记录数及内容哈希多重集合”，不能只比唯一哈希集合。A21/A30 字节相同但必须保留两个路径和两个编号。
4. 更新所有当前 Markdown 相对链接：按每份 Markdown 自身目录解析；JSON 根相对路径不能直接复制到深层 Markdown。
5. 扫描旧路径剩余引用，逐个区分：历史清单、映射、固定提交来源链接应保留；当前图册、视觉说明等应更新。不能全仓无脑替换。
6. 中文、空格、括号路径统一使用兼容普通 Markdown 的写法并验证；不引入仅 Obsidian 能识别的私有图片语法。
7. 检查 Git diff 只有预期移动、文档与索引修改；确认没有预览拼图、重复下载文件、缓存、环境目录进入提交。

不删重复图。Git 能记录路径迁移，不需要再复制一份“原始备份”把仓库体积翻倍。若迁移出错，按映射恢复相关文件或正常 revert 本轮提交；不 reset 用户后续工作。
