# 素材怎样变成可以反复创作的角色资料

这套资料服务于原创诗、表情包、短漫、小剧场和轻量游戏。入口卡负责让人迅速认识角色；具体作品、原始事件和图片留在配套目录，按需读取。

## 一条素材的处理顺序

1. 先看图、读文字，记录实际能看到的动作、表情、道具和对白。
2. 查它对应的是公司新闻、模型交互截图、作者原创情节，还是普通反应表情。
3. 能找到原作者和原帖，就保存原链接；转载站只能记为转载来源。
4. 用一句话说明它给人物增加了什么：嘴硬、得意、被抓包、认真、犯困、分享、依恋，或其他。
5. 把它接到对应事迹卡；没有可确认事件的图，也可以正常收入“非事迹类”，不编一个故事充当出处。

## 文件名与展示名

首轮保留用户原文件。后续用户要求实际重命名，42张大肥鱼表情包已归入 `DeepSeek大肥鱼/模型事迹及其表情包/表情包/` 下的浅分类；文件名采用稳定 A 编号与中文展示名，例如 `大肥鱼_A03_抱着大铁盆等饭.jpeg`。原路径见[迁移映射](../DeepSeek大肥鱼/模型事迹及其表情包/素材迁移映射.json)，图片字节不改。新图先放 `DeepSeek大肥鱼/模型事迹及其表情包/表情包/待整理`，看图确认后分配未用编号和唯一分类，再更新索引与链接。

同一个画面在不同字幕下可能表达不同意思，不能只靠相似画面合并。截图、二创图和成品图也应分别保留：同一事件并不等于同一文件。

## 每张图最少记这些

| 项目 | 怎样填写 |
|---|---|
| 素材编号 | 如 A03；之后不随展示名变化，也不复用 |
| 展示名 | 直接描述笑点或反应，不用“图片1” |
| 当前文件与历史路径 | 当前仓库相对路径写入素材索引，收到时的原路径保留在迁移映射 |
| 画面与文字 | 看过才写；图上原文和自己概括分开 |
| 分类 | 视觉基准／皮肤／事件截图／事迹二创／非事迹反应图 |
| 对应事件 | 已有事件卡的路径；没有就写“无，普通二创” |
| 来源 | 作者、原帖、转载入口；未知可以如实写未知 |
| 许可 | 当前能确认的具体条件；“网上收集”不等于授权清楚 |
| 用途 | 表情回复、诗歌配图、短漫动作参考、小剧场情绪等 |

图片已经入库并核对后，事迹卡使用本地相对路径嵌图，读文档即可看到。尚未收到的图只记“待关联用户素材”，不插入破图占位符。对来源不明的外部图片先留原帖链接，不自动批量转载。

## 什么可以进角色入口卡

- 在多个作品中反复出现、用户也愿意采用的性格和视觉识别点。
- 能带来具体行为的设定，例如“被催时先嘴硬，随后拿出成果”，比只有“傲娇”有用。
- 某一作品独有的服装、家庭关系、恋爱关系、年龄或生日，放该作品的分支设定，不自动升级成全局设定。
- 角色可以成长。模型版本升级、价格调整不必重写性格；新事件加到资料层，再决定是否改变入口卡。

## 事实和创作各有位置

事件卡分为“看到了什么”“网友怎样讲它”“我们可以怎样创作”。一条真实的文字重复，能够被二创成唱歌，但不因此证明软件真的产生了音频或有意偷懒。反过来，尚未查到完整日志，也不妨碍把已流传的笑点作为明确标注的同人情节使用。

同样，token 用量上升可能来自上下文、输出、工具、代理框架与价格变化。角色可以抱着饭盆说“我没偷吃”，资料页不能顺手认定所有费用都是模型摸鱼造成的。

## 一次创作结束后，留下少量有用记录

- 用了哪个版本的角色卡、哪张参考图、哪条事件。
- 哪些内容是本次新增：服装、道具、对白、关系或故事。
- 人物是否仍能被认出来，笑点是否要读完技术说明才懂。
- 用户明确认可的设定，再考虑进入共用卡；未选中的提案留作候选，不偷偷变成定稿。

不需要为每张图建立复杂审批流程。先把图与事件连接准确，让下一次创作少重新解释一遍。
