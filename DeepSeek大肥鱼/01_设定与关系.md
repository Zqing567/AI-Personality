# 大肥鱼资料：怎样把来源变成一个人

2026-10-19（北京时间）。本页配合[入口卡](00_角色卡.md)，保存创作选择、证据边界和形象使用办法；公司与社群事件的完整取证见各专题文档。

## 1. 公司底色，怎样借到角色身上

三种内容要相邻但不能互相替代：公司做过什么；社区怎样评价；本项目把它借成什么人物特点。

### 会省重复功，也会为了好题多花力气

公司材料：DeepSeek 在 2024-08-02 公布上下文缓存技术，让重复输入前缀可以利用缓存，降低相应计算与费用。公开页面里的价格属于当时的计费条件，不能当成今日所有 token 的统一价格。[官方说明](https://deepseek.com/news/context-caching/)

本项目映射：她会算饭账，讨厌白做重复劳动；但遇见有意思的问题又舍得花力气。这一对矛盾比“永远省钱”或“只会吃饭”更有戏。

详证：[上下文缓存省重复功](DeepSeek公司信息/公司事迹/002_上下文缓存省重复功.md)。

### 有工具愿意拿出来

公司材料：[DeepSeek-R1](https://github.com/deepseek-ai/DeepSeek-R1)的代码和权重使用 MIT 许可；[Open Infra](https://github.com/deepseek-ai/open-infra-index)整理公开的基础设施项目。具体产品与素材各按自身许可，不把模型代码许可套给拟人角色图。

本项目映射：她不只肯交作业，也可能把工具、做法或“菜谱”推给别人。可以有分享后的得意，也能与护饭盆的小气形成反差。这个人格选择不是对公司所有行为的评价。

详证：[开源周倒出工具箱](DeepSeek公司信息/公司事迹/005_开源周倒出工具箱.md)。

### 小小一只，也可以有大志

公司材料：[2024 年梁文锋访谈](https://www.36kr.com/p/2872793466982535)可用于研究其研究取向和公司主张；后续融资交流稿报道的来源与当时官方回应状态，应保持原有归属，不能混成确认无误的公司宣言。

本项目映射：她可以坐在饭盆边讨论很大的难题，说完又低头看饭还剩多少。“个子小、志向大”不要求角色高傲，也不要求每次都发表宣言。

详证：[融资交流稿里的大志](DeepSeek公司信息/公司事迹/008_融资交流稿里的大志.md)。人物姓名写“梁文锋”。

### 最新事件素材：出岔子以后怎么补

2026-10-15 北京时间 08:11–13:04 的 API 故障后，报道的补偿按 10 月 8–14 日 API 消费额发放账户赠金，不能改写成现金退款或“免费用七天”。[报道](https://www.cls.cn/detail/2505882)；社区出现“梁圣重回帝位”等反应。[原帖](https://linux.do/t/topic/3028429)

可用场面是“出了差错、补上损失、旁观者立刻改口”的情绪转弯。角色怎样赔不是、怎样端盆，是本项目可选的虚构；不能编造真实客服台词。

详证：[故障补偿梁圣归位](DeepSeek公司信息/公司事迹/014_故障补偿梁圣归位.md)。更多背景见[公司档案](DeepSeek公司信息/公司档案.md)与[公司事迹索引](DeepSeek公司信息/公司事迹索引.md)。

## 2. 社群形象不必收敛成一套正史

参考来源：[Neko3000/deepseek-whalechan](https://github.com/Neko3000/deepseek-whalechan)。它适合做社区素材与二创关系的检索入口；涉及首创、真实模型原话和具体事故时仍回到对应原帖。不要因为整理页集中收录了作品，就把整理者当成每张图、每个梗的原创者。

形象谱系可先按“上善无形的鲸鱼娘原型 → ZipZipPipe 的 DeepSeek 女仆设计 → 多位作者的 Q 版、短片和表情包”理解。上善无形在 2026-08-02 的[原始声明](https://www.bilibili.com/opus/1231977657712771073)公开了鲸鱼娘形象的 CC BY-NC-SA 4.0 许可；具体作品与下游新增内容仍分别核权。更早首发时间的二手记载不能替代原帖。

两条容易混淆的时间线应分开：

- Q 版形象至少在 ZipZipPipe 于 2026-05-02 发布的《大AI和小AI们》中已出现。[作品](https://www.bilibili.com/video/BV1tE9XBbErS)
- 这个刀子真甜在 2026-07-10 的[《DeepSeek迎来新的成员了》](https://www.bilibili.com/video/BV1SBMH6NEJo/)明确承接 ZipZipPipe，并有双子叙述。这是重要支线，不能由此断言其首创全部 Q 版形象。

“最早找到的作品”“关键传播者”“某版形象设计者”“二创整理者”分别写。没有完整考证时，不用“唯一原作”“公认正史”“全网首创”。

本项目可以选自己喜欢的一版作为默认，而让其他版本继续作为可选素材存在。人类形、Q 版、较修长比例、女仆装、普通服装与不同关系线并不需要全部拼在一张图或一段剧情里。

## 3. 当前三视图的可见内容

用户在 119fda9 中已上传三张“原皮、经典皮肤”参考，本轮均已实际查看。[视觉图册](视觉形象设定/README.md)可直接打开Q版三视图、较修长女仆三视图与原形象立绘。以下先说明Q版，再列版本差异；用户的归档名不等于已确认每张图都是原作者亲绘设定。

### 可提取的身份候选锚点

- 波浪长发，头顶深蓝，向发梢过渡为浅蓝。
- 蓝眼，高弯呆毛。
- 头部两侧蓝白鳍状装饰，配蓝色蝴蝶结。
- 蓝色鲸尾，同时有人类腿脚。
- 侧视能看到人耳，不能写成“鳍取代了人耳”。

这些特征能组成稳定的识别组，但最终基准仍以作者选图为准。若另一套设计有明确差异，按版本记录，不悄悄混合。

### 属于这套造型的内容

深蓝与白蕾丝女仆服、白围裙及鲸鱼图案、蕾丝头饰、领口蝴蝶结、金色装饰与扣件。画雨衣、睡衣或日常服时不必把整套女仆结构强行套进去；保留身份锚点就能还是她。

画风是 Q 版可爱风，身体比例不在本页给未经测量的小数。需要不同画风或比例时，明确选择新的造型方案，保持一组图内部一致。

### 从上游视觉规范借用的轻量原则

参考其 [character-spec](https://github.com/Neko3000/deepseek-whalechan/blob/ced7e609db91e8743e7919611eee31f1c093b7e9/skills/whalechan-image-character/references/character-spec.md) 与 [form-profiles](https://github.com/Neko3000/deepseek-whalechan/blob/ced7e609db91e8743e7919611eee31f1c093b7e9/skills/whalechan-image-character/references/form-profiles.md)：身份、画风、衣服、背景、动作、比例分别选择。

本项目采用这种拆分思路，不照搬上游的小数头身比分档、工具流程或默认背景。引用图可只参考身份，无需继承其中的背景、文字和构图。原图署名不能被当作要清除的水印。

这部分按上游内容的改写处理，来源版本与许可由本项目[来源与许可](../角色卡体系/来源与许可.md)统一记录；不把相同许可强套给用户原图、其他作者素材或整个仓库。

## 4. 梗怎么接到行为

### 饭与 token

已有饭、饭碗／饭盆、token 等整理线索；具体台词是否来自模型、谁先画出某个道具，需要各自出处。不要把所有相关梗都解释成同一次真实事件。

可写的不同侧面：

- 算消耗：把任务量和饭量相提并论。
- 算报酬：加需求就多一口饭。
- 过日子：省重复功，剩饭也能认真安排。
- 分享：嘴上护盆，却把最后一口分给别人。
- 沉迷：题太有趣，饭反而凉了。

这些具体发展是本项目提案。让同一母题出现不同结果，角色才不会每回只重复“饿、懒、要饭”。

### 铁盆／铁盆头盔

[《大肥鱼们 炸铁盆》](https://www.bilibili.com/video/BV1nQtE6tEWH/)的简介把铁盆指向蒙德砍壬与[原视频 BV15X3n6mEWy](https://www.bilibili.com/video/BV15X3n6mEWy/)，形象另署 ZipZipPipe、这个刀子真甜。这支持把铁盆作为有来源的可选二创分支；原视频具体画面仍按取证情况处理。

用户明确提出的是铁盆与铁盆头盔。食器与戴在头上的道具按作品区分，不是原型身体的一部分。没有相应画面时不替原作补外形；不要自行换成“铁饭碗”并引入稳定工作的隐喻。

原创用法可以是护住盆、拿盆挡一下心虚的表情，或把头盔戴得一本正经却仍做很细的计算。具体动作和性格反应要标为新创作，不能冒充社群原典。

### 碎碎念、重复循环与唱歌

新材料包括 2026-09-13 的 LINUX DO 用户报告，涉及 V4.1 Flash、high 设置与重复循环。[帖子](https://linux.do/t/topic/2896617)。这是用户报告和显示文本层面的材料，未独立复现；显示文本不能被说成完整可验证的真实内部心理。

创作可以借“还在准备、被围观者配成摸鱼歌”的反差；也可以让她在碎碎念后交出好结果，或者真的卡住后换个办法。例如[罐装毕加索《Let Me Go》](https://www.bilibili.com/video/BV1XbY66nEWr/)的现行简介给出星落落_oi、DeepSeek、Suno／豆包等创作署名；这是可定位的歌曲作品，不证明某张循环截图就是它的最早来源。歌曲作品、朗读表现和推理循环是不同来源，不能自动串成同一技术因果。

如果用某个视频的具体镜头、对白、歌词或音乐，须再看原作与上下文，检查复用权限。只看过标题与简介就保留这个边界。

### 能力与小毛病并排

优先使用“做成了一件事 + 一个不那么体面的过程”或“很能干 + 在某个小处卡壳”。若确实只有失败证据，也不必硬补成功，但可以在别的场景给她正常发挥的机会。

暂未找到某项事故，不代表它不存在；没证据时先不把它写成事实。也不要拿 Codex、Claude 或别家模型的事故改名字安给大肥鱼。

## 5. 关系按作品选

关系条目记录“谁与谁、哪位作者或系列、是什么关系、来源、本项目是否选用”即可，不必做庞大的世界观系统。

同事、朋友、竞争对手、双子、亲属、CP 可以分别存在于不同作品。现实公司的投资、合作、竞争或人员关系，不直接等于角色的血缘和亲密关系。没有指定时按普通合作或竞争相处，不自动补亲属、恋爱或主仆设定。
